Getting code into the cluster

A push to GitHub starts GitHub Actions, which builds a Docker image and pushes it to Amazon ECR. The pipeline then applies the Kubernetes manifests, and each worker node pulls the new image from ECR.

How a request arrives

Route 53 resolves the domain and CloudFront serves cached static files, then the rest of the request reaches the Internet Gateway and the Application Load Balancer in the public subnets.

Inside the worker nodes

The load balancer forwards to frontend pods, which call the backend pods through a Kubernetes service. Pods sit in private subnets with no public IP, so outbound calls leave through the NAT Gateway.

What AWS manages for you

The EKS control plane runs in an AWS-owned account across three zones. Your nodes only register with its API server. Auto Scaling adds nodes when pods cannot be placed.

Storing the data

Backend pods write to the Amazon RDS primary and read hot keys from ElastiCache. RDS replicates synchronously to the standby in the second zone, so a zone failure means a failover rather than an outage.

Keeping it safe and visible

IAM gives each pod its own role, Secrets Manager holds the database password, ACM supplies the TLS certificate, and CloudWatch and CloudTrail record what happened.

Two availability zones, public subnets for internet-facing components only, private subnets for every pod and database. Nothing in the application or data tier is reachable from the internet.
